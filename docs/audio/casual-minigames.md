## 3. 공통 엔진 계약 제안

아래 인터페이스는 설계안이며 기존 코드의 함수명으로 가정하지 않는다. 00이 공유 엔진으로 승인할 때 ID와 payload를 고정한다.

| 입력 이벤트 | payload | 음향 동작 |
|---|---|---|
| minigame_entered | chapterId, minigameId, runId | 해당 장 환경음과 음악 1개씩 준비 |
| minigame_started | minigameId, runId, mode | 첫 입력 후 준비 완료 시 시작 |
| minigame_action | minigameId, runId, actionId, objectId | 실제 움직임에 맞는 효과음. 점수 이벤트와 중복 재생 금지 |
| minigame_feedback | minigameId, runId, result, cueId | 성공/다시시도/힌트. 이미 소비한 cueId 무시 |
| minigame_paused | runId, reason | 입력 판정 중단, 예약음 정리, 음악·환경음 정지 |
| minigame_resume_requested | runId | 사용자 명시적 재개 후 새 예약 세대와 준비 카운트 |
| minigame_finished (CM-INT-001 확정) | chapterId, minigameId, runId, mode, result | result가 completed/assistedCompleted일 때만 이번 시도의 짧은 마침음. retry/exited는 성공음 없음 |
| minigame_story_confirmed (CM-INT-001 확정) | chapterId, minigameId, runId | 별도 학습 의미 활동을 마쳤을 때 1회. 추가 팡파레 없이 시각적 확인을 기본으로 함 |
| minigame_restored | runId, checkpoint | 저장 복원은 무음. 사용자 재개 후 현재 상태 음향 시작 |
| minigame_exited | runId | 음향 세대 무효화·페이드·노드 정리 |

- runId는 한 시도 동안 고정한다. pause/resume/mute는 새 시도가 아니며 audioGeneration 또는 segmentGeneration만 갱신한다. 사용자가 새로하기로 새 시도를 시작할 때만 새 runId를 만든다. 체크포인트와 점수·보상 중복 방지는 고정 runId를 기준으로 한다.
- 종료 도메인 이벤트는 minigame_finished 하나만 사용한다. minigame_completed는 발행하지 않는다. result는 completed/assistedCompleted/retry/exited이며 게임 종료만으로 학습 의미 완료 이벤트 minigame_story_confirmed를 발행하지 않는다.
- 모든 비동기 로드·디코딩·resume과 예약 요청에 runId와 audioGeneration을 넣는다. 음소거·탭숨김·장면이탈·새 플레이마다 이전 음향 세대를 무효화하고 실제 재생 직전 재검증한다.
- 음악 1개, 환경음 1개, 물체 효과음 최대 2개를 기본 상한으로 한다. ch07 연주음은 전용 관리 버스이며 타격음 꼬리가 겹칠 수 있으나 최대 동시 수는 자산 제작 후 지정한다.
- 같은 입력에서 touch와 synthetic click이 중복 음향을 내지 않도록 단일 pointer/keyboard 입력 계층과 inputId를 사용한다. 키 반복은 한 번의 연주로 처리한다.
- 현재 음소거·음량·접근성 모드를 존중한다. 늦게 로드된 이전 장의 음악을 재생하지 않는다.
- 음원 누락이나 브라우저 정책 때문에 재생이 불가능하면 무음 시각 모드로 계속할 수 있다. 소리가 로드될 때까지 진행을 무기한 막지 않는다.

## 4. CH07 창작 합주 — 시간과 판정

### 음악 시간

음악·노트·판정·시각 큐는 같은 songPosition을 공유한다. 소리가 활성화된 경우 AudioContext의 시간으로 곡 위치를 계산하고 AudioBufferSourceNode.start(when)으로 미리 예약한다. setInterval은 예약할 구간을 확인하는 보조 수단이며 박자 시계로 사용하지 않는다. requestAnimationFrame은 같은 곡 위치를 그리는 용도다.

예약 초안: 25ms 간격으로 100ms 앞까지 확인한다. 이 수치는 기기 검증으로 바꿀 수 있는 구현 초기값이다. 매 비트마다 타이머 오차를 누적하는 방식은 사용하지 않는다. 예약 큐가 늦어졌다면 지난 박자를 연달아 쏟아내지 않고 일시중지·재동기화한다.

음표는 절대 밀리초 대신 beat 단위로 저장하고, tempo·속도 모드에 따라 한 타임라인에서 변환한다. 느린 모드에서 반주 파일의 playbackRate만 낮춰 음높이가 달라지는 처리는 피한다. 시범판은 박자 기반의 개별 소리를 재예약하고, 긴 반주가 필요하면 느린 전용 음원을 만든다.

04 제안과 대조한 초기값: 기본 72BPM, 히트 ±180ms, 느긋한 모드 속도 75%(54BPM)·히트 ±350ms. 기본 연주 60초는 24박×3구간으로 제안하면 정확히 대응한다. 54BPM에서는 같은 악보 72박의 연주가 80초이므로 기본/느긋 시간을 동일 60초라고 표시하지 않는다. 준비박과 설명 시간은 연주 시간에서 제외한다. 구간 길이 24박과 위 수치는 04·00 최종 확인 후 악보 제작 기준으로 사용한다.

### 입력 보정

기본은 offset 0ms다. 시작 전 선택형 8박 맞추기 또는 수동 −250~+250ms 보정(10ms 단위)을 제공한다. 연습 2박을 제외한 입력의 중앙값으로 초기값을 제안하고 학생이 확인·초기화할 수 있게 한다. 장치·출력 전환 뒤 이전 보정이 계속 정확하다고 가정하지 않는다.

판정 부호를 고정한다: inputOffsetMs가 양수이면 관찰된 입력이 기대 박자보다 늦게 기록되는 경향을 보정한다. correctedInputTime = inputSongTime − inputOffsetMs/1000. 시각 표시 보정 visualOffsetMs는 별도로 두고 입력 보정과 두 번 적용하지 않는다. 허용 오차·점수는 04 규칙을 사용하며 음향 담당이 임의로 좁히지 않는다.

지원 시 getOutputTimestamp()로 오디오 출력 시간과 performance 시간의 대응을 구하고, 없거나 유효하지 않으면 현재 시계 쌍을 근사해 사용하되 결과를 측정된 출력 지연이라고 주장하지 않는다. 입력의 event.timeStamp와 performance 시간의 원점 호환 여부를 검사한다. 호환되지 않는 값은 단위·원점 변환 후 사용한다. 실제 블루투스·브라우저 입력 지연은 별도 검증해야 한다.

### 무음·느린 보조 모드

- 소리를 끈 경우 같은 beat chart를 performance.now() 기반의 단조 타임라인으로 구동한다. AudioContext가 suspend된 상태의 currentTime에 의존하지 않는다.
- 소리 없이도 준비박·다가오는 박·판정 위치·입력 결과가 모양과 글자로 보인다. 색만으로 구별하지 않는다.
- 느린 보조 모드는 템포를 낮추고 04가 지정한 넓은 판정창을 사용한다. 능력 평가·역사 이해 점수와 속도 기록을 섞지 않는다.
- 연습·일반·느린·무음 모드를 명시해 기록한다. 다른 모드의 기록을 같은 속도 경쟁 랭킹으로 비교하지 않는다.
- 음소거 전환 자체로 불이익이 발생하지 않게 해당 구간을 일시중지하고 모드를 바꾼 뒤 준비박부터 다시 시작한다.

### 중단·재개

1. 탭숨김·포커스 이탈·설정/대화창 열기·AudioContext 중단을 감지하면 입력과 판정을 먼저 멈춘다.
2. 예약 노드를 중지하고 audioGeneration/segmentGeneration을 갱신한다. runId는 유지한다. 이전 노드의 onended와 늦은 resume은 현재 게임을 진행시키지 못한다.
3. 다음 재개 위치는 04가 지정한 짧은 구간의 시작점이다. 중단한 구간의 임시 판정·미스·콤보 변화를 취소하고 마지막 확정 체크포인트만 유지한다. 같은 구간을 재개해 점수를 중복 획득하지 않는다.
4. 사용자가 ‘계속’을 누르면 현재 모드·음소거·화면 가시성·오디오 준비 상태를 확인하고 **4박 준비 카운트**를 소리와 시각(무음은 시각만)으로 보인다. 준비박은 점수 판정에서 제외한다.
5. 준비박 종료 시 새로운 곡 기준 시각을 잡아 해당 구간을 시작한다. 숨겨진 동안 지난 노트를 미스로 처리하거나 복귀 시 누적 미스를 발생시키지 않는다.

## 5. CH04 이동·레이싱과 실패 피드백

목표는 피란민에게 필요한 물자를 안전하게 운반하는 것으로 두고 순위·폭력·전쟁 피해를 경쟁 보상으로 삼지 않는다. 바퀴/발걸음은 현재 이동 속도에 연결하되 프레임마다 새 효과음을 생성하지 않는다. 장애물 경고는 시각 경고와 같은 cueId로 한 번만 제공하고, 동일 경고가 연속으로 겹치지 않게 한다. 좌우 스테레오만으로 방향을 알려 주지 않는다.

넘어짐·충돌은 낮은 ‘툭’과 수레의 멈춤 정도로 표현한다. 비명·피해자의 울음·큰 경적은 제외한다. 실패 시 음악을 과장되게 끊거나 조롱하는 부저를 넣지 않고 ‘다시 출발해 보자’라는 글과 짧은 숨 고르기를 제공한다. 다음 시도·느린 보조를 즉시 선택할 수 있으며, 재시작은 출발 카운트 이후 진행한다.

다른 장에서도 실패는 정보로 전달한다. 반복 실패음은 800ms 재생 제한을 두고, 단순 입력 대기에는 경고음을 울리지 않는다. 역사적 판단이 필요한 선택에서는 속도 미스와 개념 오류를 다른 문구로 설명한다.

## 6. 검증 계획과 근거

현재는 설계 검토 단계다. 다음 항목은 실제 구현·청취 후 검증해야 한다.

- 크롬북·태블릿에서 일정한 입력이 같은 박으로 판정되는지, 스피커/유선/블루투스 출력별 보정 차이.
- 1분 이상 연주에서 음악과 노트가 누적 이탈하지 않는지, 늦은 프레임에서 지난 음이 몰려 나오지 않는지.
- 모든 박 위치에서 탭숨김·AudioContext 중단·음소거·재개 후 누적 미스·이중 점수·지연 재생이 없는지.
- 무음·오디오 로드 실패·느린 보조 모드만으로 모든 장을 끝낼 수 있는지.
- 동시효과음·반주·대화가 겹칠 때 갑작스러운 큰 소리·클리핑·정보 손실이 없는지.

기술 사실의 확인 출처(2026-11-18): [W3C Web Audio API 편집 초안](https://webaudio.github.io/web-audio-api/)의 currentTime, 예약 start(), getOutputTimestamp()와 [High Resolution Time](https://www.w3.org/TR/hr-time-3/)의 단조 시간 정의. 편집/작업 초안은 변경될 수 있다. 예약 간격·보정 범위·카운트·버스 정책은 이 프로젝트의 설계 제안이다.

- 05 → 03 CM-AU-01(P2 설계 위험): pause/resume에서 runId를 갱신하면 새 시도로 오해하여 점수·체크포인트 중복을 유발할 수 있음을 지적함. v0.2에서 runId 고정·음향/구간 세대만 갱신·새로하기만 새 runId로 명확화했다. 실제 버그 관찰은 아니며 재확인 요청 상태다.
- 05 재확인: v0.2의 runId 고정·세대만 갱신·새 시도만 새 ID를 실제 문서에서 확인하고 문서상 보완 완료를 회신했다. 구현 검증은 아니다.
- 00 CM-INT-001 확정(v0.3): 종료는 minigame_finished와 지정 payload/result로 통일, 별도 학습 의미 완료는 minigame_story_confirmed로 분리. minigame_completed 제안 폐기와 게임 종료→학습 완료 자동 발행 금지를 반영했다.
- 03 → 04(v0.4): 8개 활동명을 실제 파일에서 확인해 음향표를 정렬했다. 72BPM×60초=72박, 24박×3구간과 54BPM 느긋 모드 80초를 제안하고 구간 롤백·콤보·임시 점수 확정을 질의했다.
- 회신 반영과 재확인은 이후 기록한다. 실제 음원과 플레이를 검증한 것으로 표시하지 않는다.

### 2026-11-19 총괄 통합 확인
게이밍 v0.3 §11-1에서 72박(24박×3구간), 72BPM 약60초·54BPM 약80초, 동일 템포 지도에 따른 반주/시각/판정 동기화, 4박 재개 준비와 미완료 마디 점수 롤백, 단일 minigame_finished 이벤트를 반영했다. 실제 반주 제작과 타이밍·청취 검증은 남아 있다. 기존 사운드 담당의 추가 재검토를 완료했다고 주장하지 않는다.
