# 실행 구현 검증

검증 담당: runtime_qa / 2026-11-19

## 환경

- Windows, 실제 Chrome 실행 파일을 headless 모드로 실행한다.
- 기존 런타임의 Playwright를 사용한다. 별도 패키지 설치는 하지 않았다.
- 브라우저가 생성한 페이지에서 버튼을 실제 클릭하는 기본 동작을 확인했다.
- 일반 개발 서버 `127.0.0.1:4173`은 별도 실행 세션에서 접속 시간 초과가 발생했다. 검증 프로세스 안에 정적 HTTP 서버를 함께 실행하여 `127.0.0.1:4180`과 `4181`에서 실제 원본 HTML·ES 모듈·CSS·이미지를 제공했다.
- 최종 검증은 요청을 가로채는 route 방식이 아닌 실제 HTTP 전송이다. 중간 진단에만 원본 바이트 route 방식을 사용했다.

## 범위와 증거 구분

브라우저의 마우스/키보드 이벤트로 UI를 조작한다. 내부 완료 상태를 주입하거나 저장 데이터를 정답 상태로 바꿔 통과시키지 않는다. 브라우저 화면 크기를 태블릿·크롬북 기준으로 맞춘 검사는 실제 하드웨어 터치 검증과 구분한다.

| 검사 | 목표 |
|---|---|
| 화면 | 1024×768, 768×1024, 1366×768에서 문서 전체 스크롤과 UI 잘림 없음 |
| 진입 | 8개 장 모두 시작·안내·게임 진입 가능 |
| 조작 | 도움 모드도 최소 참여를 직접 수행한 뒤 종료 가능 |
| 재시도 | 결과의 다시하기가 새 게임을 만들고 중복 입력/루프를 남기지 않음 |
| 일시정지 | 정지 중 시간과 입력 판정이 진행하지 않음 |
| 저장 | 완료 뒤 새로고침에서도 완료 표시 유지 |
| 키보드 | Tab·Enter 등 실제 키 이벤트로 주요 조작 가능 |
| 오류 | pageerror 및 관련 콘솔 오류를 수집하여 보고 |

기본 결과 JSON에는 58개 관찰 기록, 긴 일반 모드 검사에는 4개 관찰 기록이 있다. 관찰 기록 수를 독립적인 테스트 케이스 수나 실기기 수로 세지 않는다.

### 발견·수정·재확인

1. CH08 투명 관찰 버튼의 클릭을 풍경 SVG가 가로채고, 전역 `button:active` 변환이 중심 이동 변환을 덮어써 클릭이 실패했다. 총괄이 장식 SVG의 pointer-events와 관찰 버튼의 active 변환을 보완했다. 강제 클릭 없이 정상 locator 클릭으로 네 물건을 관찰하고 완료한 것을 재확인했다.
2. 게임 장면의 CSS 변수에 상대 이미지 URL을 넣어 `css/assets/scene-*.webp`로 잘못 요청하는 404를 발견했다. 총괄이 document.baseURI를 기준으로 절대 URL을 만들도록 수정했다. 최종 전 구간 재실행에서 해당 404와 콘솔 오류가 사라졌다.

### 재현과 증거

- 실행 스크립트: `tests/browser-check.cjs`.
- 환경 변수 `EMBEDDED_SERVER=1`로 같은 프로세스 정적 HTTP 서버를 사용한다. `ONLY_LONG=1`, `BASE_URL=http://127.0.0.1:4181`은 실제 시간 레이싱·리듬 검사다.
- `PLAYWRIGHT_MODULE`과 `CHROME_PATH`로 다른 설치 경로를 지정할 수 있다. Playwright가 일반 require 경로에 없으면 이 실행 환경의 기존 런타임 패키지 경로를 사용한다.
- 기본 로그: `test-results/browser-results.json`.
- 실제 시간 로그: `test-results/browser-results-long.json`.
- 대표 화면: `home-1024x768.png`, `game-6-1024x768.png`, `normal-live-4.png`, `normal-live-7.png`. 같은 디렉터리의 세 화면 크기별 게임 스크린샷도 저장했다.
- 화면 검사는 DOM의 읽기 전용 기하 정보와 실제 화면 이미지로 확인했다. 앱 완료 변수·정답·게임 시계를 직접 변경하지 않았다.

## 미검증 범위

실제 태블릿·크롬북 기기, 손가락 터치, 모든 장의 키보드 전용 완주, 학생의 재미·난도·학습 효과, 실제 스피커 출력과 음향 지연, 배포 URL에서의 통합 실행은 별도 검증이 필요하다. 768×1024·1366×768에서는 각 게임 진입과 초기 화면 배치를 검사했으며 해당 크기에서 전 게임 완주를 반복하지 않았다. 새로고침 검사는 완료 보존을 확인한 것이며 모든 장의 중간 상태 복원까지 확인한 것은 아니다.
