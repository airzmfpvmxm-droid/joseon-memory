# CH06-002 곡식 창고 플레이 명세

버전: v0.3 / 2026-11-18 / 담당: 04 게이밍 / 상태: 01·02·03·05 및 총괄 교차검토 반영, 총괄 승인 대기
기준: 운영 v1.0, PROJECT.md, CHAPTERS.md, IDENTIFIERS.md. 관련 시나리오: docs/story/ch06-warehouse.md.
범위: 시범 구간의 규칙·상태·조작·복구 명세. 코드 구현 및 실제 플레이 검증은 미실시.

## 독립 설계의 목표

주민의 사연을 듣고, 약속한 상환 조건과 별도 요구를 직접 대조한 뒤, 근거를 주민에게 설명한다. 계산만 맞히거나 이자가 있다는 사실만으로 부정을 단정하면 완료되지 않는다. 대화와 단서 위치를 감추어 클릭을 반복하게 만드는 방식은 쓰지 않는다.

성취: ① 대여와 부정 운영의 차이 이해 ② 주민 증언과 기록의 역할 구별 ③ 관찰·비교에 근거해 판단 ④ 작은 도움과 사회 전체 해결의 범위 구별.

## 시범 사례 데이터 — 게임용 가상 설정

| 항목 | 수치/근거 | 해석 |
|---|---|---|
| 봄 지급 | 10되 | 주민 증언과 본인 확인된 교부 기록이 일치 |
| 처음 안내된 이자 | 1되 | 이 사례의 가상 약정. 당시 일반 이율로 제시하지 않음 |
| 약정 상환 | 11되 | 지급 10되 + 안내된 이자 1되 |
| 가을 요구 | 15되 | 주민이 손에 펼쳐 보여 주는 요구 쪽지에 적힘 |
| 추가 요구 | 4되 | 요구 쪽지의 '아전의 몫 4되' 행. 약정 기록에 없는 임의 요구 |
| 곡식 표본 | 벌레 먹은 곡식 | 부정 운영 맥락의 보조 관찰. 농민이 봄부터 보관한 표본과 빌릴 때부터 그랬다는 증언을 함께 확인. 과거 지급 상태·전체 품질·양을 외형만으로 증명하지 않음 |

정상적인 곡식 대여와 합의된 이자 자체를 범죄라고 설명하지 않는다. 이번 판단은 확인된 약정 11되와 그 밖의 사적 추가 요구 4되의 불일치에 근거한다. 역사 사실·창작 수치의 표시는 교사용 명세/자료 출처에서 구분하되 장면 안에 개발자 안내문을 떠 있게 하지 않는다.

## 흐름과 예상 길이

시범 목표 6~9분(제작 전 추정). 최초 진입 → 농민과 대화(1분) → 기록·표본 조사(2분) → 비교 작업(2~3분) → 보고와 변화(1분). 시간 제한·목숨·실패 벌점은 없다.

1. 입구에서 쌀자루를 붙잡은 농민을 발견한다. 첫 하단 목표는 '창고 앞 농민의 이야기를 들어 보자'. 농민 가장자리의 작은 별만 간헐적으로 표시한다.
2. 농민의 짧은 대화가 끝나면 요구 쪽지 ch06_demand_note를 농민이 손에 펼쳐 보여 준다. 소유권은 농민에게 유지되고 플레이어는 관찰한 내용의 자료 보기에서 재열람할 수 있다. 쪽지 자체의 별도 장면 클릭 영역은 만들지 않고 농민 대화/자료 보기에서 열람한다. 농민은 '봄에 적은 기록은 뒤쪽 낮은 탁자에, 작은 곡식 꾸러미는 제 옆 바닥에 있어요'라고 직접 안내한다. 총괄 INT-001 기준 표본 앵커(.43,.89), 탁자에는 기록만 배치한다.
3. 기록·요구 쪽지·표본은 순서와 관계없이 조사 가능하다. 아직 조사하지 않은 대상만 은은하게 반짝인다. 세 자료를 확인한 뒤 '약속과 요구를 나란히 확인하자'로 목표가 바뀐다. 곡식 관찰의 목적은 주민이 보관한 벌레 먹은 곡식과 빌릴 때부터 그랬다는 증언을 함께 확인하는 것이며 추가분의 계산 근거로 취급하지 않는다.
4. 세 조사 완료 뒤 농민에게 다시 말하거나 기록의 '비교하기'를 선택하면 한 개의 비교 겹창이 열린다. 선행 조사 없이 비교를 선택하면 남은 자료와 위치를 안내하며 입력창은 열지 않는다. 요구 쪽지 확인도 다른 자료처럼 정식 조사 완료 이벤트를 거친다.
5. 지급 10되와 이자 1되를 상환 칸에 놓아 11되를 재구성한다. 요구 15되와 차이 4되를 표시하고, 차이에 해당하는 요구 쪽지의 추가 행과 봄 기록을 연결한다.
6. 계산·근거 확인 뒤 실제 장면으로 돌아가 농민에게 보고한다. 약정11되와 추가4되를 설명하고, '빌릴 때부터 벌레 먹은 곡식이었다는 사정도 함께 전할게요'(ch06_report_001b)로 표본 관찰의 결과를 함께 남긴다. 농민은 앉은 채 몸을 조금 펴고 플레이어를 바라보며 쪽지를 다시 챙긴다. 빈 자루를 움켜쥔 손이 풀린다. 이는 조사를 돕고 진술을 정리한 결과이며 세금 취소·아전 처벌·전국 문제 해결로 묘사하지 않는다. 일어서기와 자루 이동은 이번 시범 필수 범위가 아니다.

## 비교 활동 규칙

- 비교 겹창 상단: '봄에 안내된 조건 / 가을에 요구한 양'을 동시에 보여 준다. 사람 이름·지급10·이자1·약정11·요구15·추가행은 확정 대사와 같은 데이터에서 생성한다.
- 자료 원문은 '기록 펼치기'와 '요구 쪽지 펼치기'로 쪽을 바꿔 본다. 닫으면 입력과 초점이 유지된다. 장면·자료·비교의 겹창을 동시에 여러 개 쌓지 않는다.
- 탁자 위 비교판에 지급 10되를 나타내는 한 묶음과 이자 1되를 나타내는 계량 그림을 놓는다. 표현은 수량 비교용 모형이며 실제 쌀자루 하나가 1되라는 뜻으로 그리지 않는다. 26번 반복 클릭하여 세는 활동은 피한다.
- 기본 입력은 '선택 → 놓을 칸 선택'. 드래그는 선택적으로 지원하며 필수가 아니다. 초기 모형은 10, 1, 4 묶음으로 구성한다. 4 묶음은 요구의 추가분 칸에서 사용한다.
- '약속대로 갚을 양'에 10+1을 놓으면 11되. 요구15와 나란히 놓고 '더 요구한 양'에 4를 놓는다. 모형을 옮겨도 기록의 실제 숫자는 바뀌지 않는다.
- 마지막에 초과분의 근거를 연결한다: 봄 기록의 약정11 + 요구쪽지의 사적 추가4. 곡식 표본만 고르면 '곡식 상태는 확인했어. 더 요구한 양은 어느 기록에서 확인할까?'라는 도움말을 준다.
- 성공 조건은 조사 선행 조건 + 11되 구성 + 차이4되 + 약정/추가행 근거 연결이다. 정답만 추측해도 조사 없이 통과할 수 없다.
- 색만으로 정답/오답을 구분하지 않는다. 숫자·단위·문장·선택 표시를 함께 사용한다. 양을 줄일 때 굶주림을 벌점처럼 연출하지 않는다.

새 ID는 총괄 CH06-003 승인 전까지 제안 상태다. 이벤트를 다시 읽어 사운드를 재실행하지 않는다. 재열람은 자료 열기 행위음만 낼 수 있다.
자료 열기 행위는 공통 ui_document_opened에 objectId를 전달한다. 자료별 *_opened 이벤트를 추가하지 않는다. *_checked는 첫 학습 상태 변경이며 UI 열기와 분리한다. 구체적 음향은 docs/audio/ch06-warehouse.md를 따른다.
시범의 기본 수량 모형은 선택→배치다. 실제 곡식을 붓는 시각 동작을 구현하지 않았다면 ch06_grain_poured와 곡식 붓기 소리는 발생시키지 않는다. 단순 숫자 변경·자료 확인에 붓기 소리를 붙이지 않는다.

## 입력·레이아웃·접근성

- 마우스: 실제 인물/소품 클릭, 비교 모형 선택 후 배치, 선택적 드래그.
- 터치: 한 번 누르기만으로 모든 진행 가능. hover·더블탭·정밀 드래그를 요구하지 않는다. 연속 빠른 입력은 한 번만 반영한다.
- 키보드: Tab/Shift+Tab으로 현재 장면의 상호작용 대상과 대화 조작 이동, Enter/Space로 선택. 비교 항목도 같은 방식. Esc는 자료/비교 창 닫기이며 전체 진행 초기화가 아니다.
- 겹창을 열면 초점을 창 안에 두고 배경 입력을 막는다. 닫으면 호출 대상에 초점 복원. 더 이상 없는 대상이면 농민 또는 현재 목표로 복원한다.
- 이미지와 같은 위치의 투명 영역을 확보하되 인접 영역 겹침은 허용하지 않는다. 44×44 CSS px가 어려운 자료는 확대 조사 창에서 처리한다.
- 1024×768 가로를 기준으로 한 화면 구성. 768×1024 세로는 재배치로 대응. 장면 높이가 줄어 농민이 대화창에 가려지면 얼굴·손 동작이 보이는 구도로 조정한다. 전체 페이지 세로 스크롤 금지.
- 비교의 자료2개·현재 계산·선택·닫기·도움말을 한 화면에 둔다. 긴 원문은 쪽전환. 좁은 화면에서는 원문을 동시에 펼치지 않아도 두 자료 요약과 비교 수치는 함께 보인다.
- 반짝임: S0 농민만, S1 미조사 대상 각각, S2/3 비교 진입 대상, S4 농민만. S5 임무 반짝임 없음. 일반 관찰물은 hover/focus로 구분한다. 움직임 줄이기 설정에서는 고정 작은 표시와 초점으로 대체한다.

## 힌트·오답·중단·복구

| 상황 | 피드백/복구 |
|---|---|
| 어디를 조사할지 모름 | 현재 목표 선택 또는 농민 재대화로 탁자·표본 위치를 말로 안내. 사물 주위 사각 빛 테두리 없음 |
| 이자를 제외해 10되로 구성 | '처음 함께 약속한 이자도 기록에서 찾아볼까?' 관련 행을 잠깐 강조 |
| 15되 전부가 부정이라고 판단 | '받은 곡식과 처음 약속한 양을 먼저 나누어 보자' 정상 상환과 추가 칸 분리 |
| 표본만 부정 추가분의 근거로 연결 | 표본으로 알 수 있는 범위와 수량 기록의 역할을 짧게 설명 |
| 오답 반복 | 1단계 질문형 힌트 → 2단계 관련 행 강조 → 요청 시 한 단계 시범. 답 전체를 자동 완료하지 않음 |
| 비교 닫기·장면 이탈 | 초안 입력·조사 상태 저장. 재개하면 같은 단계와 현재 목표 표시 |
| 새로고침/브라우저 종료 | 마지막 저장 상태에서 복원. 이미 들은 첫 대화나 성공음을 강제 재생하지 않음 |
| 저장 실패 | 세션 내 완료와 다음 목표 진행 유지. saveStatus=failed를 표시하고 재시도 제공. 저장 성공인 척 다음 접속 보존을 약속하지 않음 |
| 이미지 로드 실패 | 이모지 대체 금지. 총괄 공통 복구 UI에서 같은 근거를 읽고 조사할 수 있게 해 진행 차단 방지 |
| 완료 뒤 재입장 | 몸을 편 농민·손을 풀고 챙긴 쪽지·회고 대사 유지. 완료 보상·이벤트 중복 지급 없음 |

## 저장 계약 제안

키 예: joseonMemory.save.v1, chapterId=ch06, sceneId=ch06_warehouse, schemaVersion=1. 기존 게임의 저장 키와 분리한다.
저장 항목: farmerTalked, demandAvailable, demandChecked, recordChecked, grainChecked, comparisonDraft(모형 배치·근거 연결), comparisonCompleted, farmerReported, hintLevel, lastSafeFocusId. demandAvailable은 열람 가능 상태이며 획득·소유권 이전을 뜻하지 않는다. 별도 런타임 saveStatus=pending/saved/failed로 저장 결과를 안내하며 이 값이 학습 완료를 취소하지 않는다.
상태명은 위 플래그에서 파생한다. 읽기 시 farmerReported⇒comparisonCompleted⇒세 조사완료⇒farmerTalked를 검증한다. 깨진 의존 관계는 마지막 일관된 단계로 복구하고 전부 초기화하지 않는다. 잘못된 JSON/지원하지 않는 버전은 기존 데이터를 보존한 채 복구 안내를 제공한다.
저장 시점: 안정적인 대화/조사 완료, 비교 입력 확정, 보고 종료, 장면 이탈 전. 드래그 중간 좌표나 음향 재생 중 여부는 저장하지 않는다. 구체적 저장 구현·마이그레이션은 00 담당.

## 교차검토 기록

- 04 초기 독립안: 증언 후 병렬 조사, 비교 겹창에서 약정 재구성, 근거 연결과 보고를 분리.
- 01 협의: 10+1=11 / 요구15 / 추가4의 가상 사례 채택. 지급량은 기록+증언, 표본은 보조 관찰로 구분함. ch06_demand_note 추가 제안 반영.
- 02 협의: 단일 겹창, 선택→배치와 키보드 대안, 자료2개 동시 요약 요청.
- 03 협의: 최초성공·재열람·저장복원의 음향 분리, 행위 이벤트와 영속 상태 구분 요청.
- 05 GP-01(P1): 비교 조기진입과 3자료 선행조건의 충돌 지적. 세 조사 완료 후만 비교 허용으로 수정.
- 05 GP-02(P2) 및 총괄 P1: 요구쪽지 소유권·표본 위치·주민 최종자세·되/비교모형 역할 불일치 지적. 총괄 INT-001에 따라 농민소유쪽지(별도 클릭영역 없음)·농민옆바닥표본(.43,.89)·앉아몸펴기, 실제되 일반관찰과 겹창모형 분리로 수정. 탁자옆표본 중간 제안은 폐기.
- 05 GP-03(P2) 및 총괄 P1: 저장실패가 학습완료를 막는 조건 지적. 세션 내 완료와 영속 저장 결과를 분리.
- 05: 표본 관찰은 수량 판단의 근거가 아니라 주민의 곡식 상태 증언 확인임을 목표·대사로 명시할 때 수용 가능하다는 의견 반영.
