# 장면 탐험 1차 구현 — 2026-11-20

이야기 모드의 각 장을 ‘장면 도착 → 주민 발견·접근 → 대화 → 놀이 → 같은 주민에게 귀환 → 기억 복원’으로 연결했다.

## 조작과 저장

- 바닥 클릭·터치, 방향키 또는 WASD로 여행자를 이동한다. 주민을 누르면 가까운 위치로 걸어간 뒤 대화를 연다. 가까이에서는 ‘대화하기’ 또는 Enter를 사용할 수 있다.
- 각 장의 이동 가능한 길을 직사각형 범위로 제한한다. 전체 풍경의 자유 보행, 복잡한 장애물 우회 경로 탐색, 장면 사이 실시간 이동까지 구현한 것은 아니다.
- 배경에 주민이 이미 있는 1·4장은 그 인물의 그림을 직접 선택한다. 없는 장면은 투명 인물 삽화를 배치하며 6장은 기존 농민 삽화를 사용한다.
- 현재 주민 가장자리에 작은 별이 나타났다 사라진다. 일반 조사 대상은 배경 속 문·책상·지붕·곡식 자루 등의 위치에 보이지 않는 영역을 배치하고 hover·키보드 선택 때 이름을 표시한다.
- `story.position`, `story.met`, `story.looked`에 위치·만남·조사 기록을 저장한다. 기존 이야기·놀이 기록은 유지한다. 관계는 첫 만남·인사·부탁·귀환의 진행 반응이며 호감도·선택 분기는 아직 없다.
- 배경·인물 로드를 확인하기 전에는 로딩 안내를 표시한다. 이미지 누락을 이모지로 대체하지 않는다.

## 장별 대상

| 장 | 대화 대상 | 배경 조사 |
| --- | --- | --- |
| 1 | 배경에 그려진 목수 | 한양의 문 |
| 2 | 종이를 든 주민 | 마당의 책상 |
| 3 | 이웃 | 집의 지붕 |
| 4 | 배경의 주민 | 들판 |
| 5 | 화성의 일꾼 | 작업장 |
| 6 | 기존 피해 농민 | 곡식 자루 |
| 7 | 북을 든 광대 | 장터의 가게 |
| 8 | 뱃사람 | 마을 풍경 |

기존 삽화 재사용에 따른 장소 표현의 한계가 있다. 5장은 별도 화성 공사 배경이 아니라 기존 작업장 삽화, 8장은 별도 나루터 배경이 아니라 마을 전경을 사용한다. 시대·장소는 제목과 대사로 표시한다. 이를 완성된 역사 장면 고증으로 주장하지 않는다.

## 검증

Chrome + Playwright로 8장 접근·대화·도움 모드 놀이·귀환·그림 복원·결말을 이어서 검사했다. 첫 장에서 실제 방향키 이동, 배경 물건 조사, 새로고침 후 대화 이어가기도 확인했다. 완료 상태와 게임 시계는 주입하지 않았다.

1024×768에서 8개 장면, 768×1024와 1366×768에서는 첫 장 탐험·대화와 홈·도입을 검사했다. 배경과 인물의 로드가 끝난 상태에서 캡처를 확인했다. 배경 속 인물 중복, 물가의 초기 위치, 책상 위 인물 배치를 확인하고 수정했다. 기존 미니게임 검사도 통과했다. 학생 이해도와 재미, 실제 태블릿·크롬북 기기, 모든 이동 좌표와 모든 화면 조합은 미검증이다.

파일: `js/exploration.js`, `css/exploration.css`, `assets/exploration-characters.png`, story-flow·save-state·app 연결. 통합 검사는 `tests/story-flow.cjs`.

배포 소스 `b167903f3d77c5a4aca09dfe78d1e4bf50ce725b`의 배포 상태 `succeeded`를 확인했다. 실제 배포 주소에서 같은 통합 검사를 재실행해 8장 접근·도움 모드 놀이·귀환·결말, 방향키 이동·배경 조사·대화 저장, 위 세 크기의 해당 화면을 통과했다. 검사에서 페이지 예외·실패 HTTP 응답은 기록되지 않았다. 실제 기기나 학생 이해도를 검증했다는 뜻은 아니다.
